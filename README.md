# Система учёта времени сотрудников

Трекер рабочего времени для сотрудников (в т.ч. удалённых). Время засчитывается
только пока сотрудник сам держит сессию "начатой" — включённый компьютер сам
по себе ничего не значит. Сессия закрывается либо кнопкой "Закончить работу",
либо автоматически при выключении/выходе из Windows.

Часы попадают в Google-таблицу
["Система учета времени ОП"](https://docs.google.com/spreadsheets/d/107351O09XVj8TrWHF5lOTPocDpISgytuTv9iW5aHtyM)
на лист "Часы" (боевой, переключение со служебного "Тест" на "Часы" сделано
сменой Script Property `TARGET_SHEET_NAME` в Apps Script, без передеплоя).
Это отдельная таблица от ручного табеля HR ("График МП") — они не пересекаются.

## Состав

- **`backend/`** — Google Apps Script Web App, привязанный к таблице. Принимает
  события старт/стоп/heartbeat от клиентов и пишет строки сессий в таблицу.
  См. `backend/SETUP.md` для деплоя.
- **`client/`** — трей-приложение на .NET 8 WinForms для Windows. Кнопка
  старт/стоп в трее, иконка-секундомер с бейджем состояния, автозапуск,
  локальная очередь на SQLite (WAL) с автосинком, переживает отсутствие
  интернета и падения процесса. Собранный self-contained билд лежит в
  `client/publish/TimeTracker.exe` — один файл, не требует установки .NET
  на машине сотрудника.
- **`docs/VERIFICATION.md`** — чеклист ручной проверки всей системы целиком.

## Как это работает

1. Сотрудник включает компьютер — приложение стартует автоматически (трей),
   но **время не считается**, пока не нажата кнопка "Начать работу".
2. Пока сессия активна — тикает локальный таймер, событие уходит в очередь
   и синкается с таблицей в фоне.
3. Сессия закрывается вручную кнопкой, либо автоматически при выключении/
   выходе из Windows, либо (после сбоя вроде BSOD/отключения питания) —
   восстанавливается при следующем запуске приложения по последнему
   зафиксированному heartbeat.
4. Если интернета нет — события копятся локально и досылаются сами, как
   только связь появится. Сотруднику для этого ничего делать не нужно.

## Статус

Всё реализовано и проверено вживую, включая офлайн-режим и восстановление
после эмулированного краша (`Stop-Process -Force` без штатного завершения) —
см. подробный чеклист в `docs/VERIFICATION.md`. По пути найден и починен
реальный баг: без `SpreadsheetApp.flush()` в Apps Script и без WAL-режима +
`busy_timeout` в SQLite конкурентные запросы могли не увидеть только что
записанные данные — оба места исправлены.

## Боевой запуск

`TARGET_SHEET_NAME` уже переключён на `Часы` — система пишет в боевой лист.
Осталось раздать `client/publish/TimeTracker.exe` сотрудникам — один файл,
при первом запуске сотрудник вводит своё имя, дальше приложение поднимается
в трее автоматически при каждом входе в Windows.
